# CPU対戦の設定と確認

CPUはプレイヤーと同じGameConfigを使います。初期手札、手札上限、先攻初回ドローなし、ターン開始時のコスト増加、1ターン1行動、防御時のカード消費、山札切れを双方に適用します。防御は従来のプレイヤーと同じくコストを払いません。次の防御倍率は、実際に防御カードを使ったときに消費します。

## 設定

- タイトルのスタートから「やさしい / ふつう / むずかしい」を選び、「キャラクター選択へ」で進みます。選択は保存され、次回の対戦にも反映されます。
- タイトルでまだ難易度を選んでいない場合は、BattleStateMachineのCPU欄のCpu Difficultyを使用します。Inspectorの初期値はNormalです。
- Enemy Deck Definitionを指定すると、その固定デッキを使います。
- 未指定なら、Assets/Resources/CPU/DefaultCpuConfig.assetの難易度別デッキ、次にDefault Deckを使います。付属デッキは現在のGameConfigに合わせた20枚、各カード2枚以下です。デッキ上限を変えた場合はCPUデッキも調整してください。
- デッキの枚数・同名上限が不正ならConsoleに設定エラーを表示し、対戦を開始しません。
- Cpu Configも差し替え可能です。Create > Qpic > CPU > Battle Configで設定アセットを追加できます。

カード演出の初期値は拡大0.16秒、表示1.5秒、戻り0.18秒です。キャラクター参照がない場合のReveal Positionは中央から左に500、上に300、Reveal Scaleは0.7です。用途を文字と色で表示し、攻撃の場合はその後に防御選択を受け付けます。演出はクリックを遮りません。必要なUIは既存Canvasとフォントから実行時に生成するため、Battleシーンへの追加配置は不要です。

## 難易度

- Easy：支払い可能なカードの合法な用途からランダムに選びます。防御を見送る場合もあります。
- Normal：攻撃、回復、ドロー、効果の価値を採点し、倒せる効果ダメージを優先します。
- Hard：次の自分の行動で使える攻撃カードと攻撃倍率の組み合わせ、防御の過剰消費、攻撃力の高いカードの温存も評価します。

AIに渡すのは自分の手札と公開されているHP等だけです。相手の非公開の手札や山札順は参照しません。現段階は評価式による判断で、対戦を通じた学習はしません。

## 効果と対戦進行

「進捗確認」はそのカード自身を効果として使用できないだけで、手札にあっても講座など他のカードの効果は使用できます。プレイヤーとCPUは同じカード単位の使用条件を参照します。手札にある間のターン終了時1ダメージは維持します。効果詳細の説明も「このかーどはこうかとしてつかえません」とし、他のカードまで禁止する表現は使用しません。

CPUの使用カードはScale 0.7（従来1.4の半分）、相手キャラクターの左端から24の間隔を空けた位置に小さく表示します（キャラクター参照がない場合は(-500,300)）。画面の端に出ないようカードと見出しの位置を補正します。カード画像をクリックすると背景付きの詳細を開き、カード・背景のクリックかEscで閉じます。詳細は防御/スキップなどの背後の操作を遮り、閉じると同じ選択待ちへ戻ります。通常カードの表示時間は詳細を読んでいる間だけ停止します。カードを戻す際やUIを破棄する際には詳細も閉じます。

防御の案内は中央の青い帯（最大660×76、18〜26の文字サイズ）へ変更しています。カード画像以外の通常表示や案内帯は操作を遮りません。

CPU側の常設情報は「やまふだ N」だけを表示します。プレイヤーの山札ラベルを複製し、同じフォント・サイズ・色でCPUのHPの数字の右端から24の間隔を空けて置きます。HPの透明なテキスト領域ではなく描画された数字を基準にするため、広い領域が設定されていても山札が画面外へ押し出されません。難易度・手札・コストは盤面には表示しません。画面中央のCPU行動説明と、左のターン表示に攻撃値を重ねる表示も行いません。防御待ちには「ぼうぎょするか、すきっぷをえらんでください」を表示し、防御カードの選択とスキップボタンを利用できます。

双方の常設の効果欄（白枠）は非表示にし、効果の内容はキャラクタークリックで開く詳細パネルへ集約します。効果の計算・有効期限は変えません。CPUのカード拡大演出と、そのカードの用途表示は維持します。

攻撃は相手の防御カードで軽減します。効果ダメージは従来どおり通常の防御選択を挟まずに処理します。回復、ドロー、コスト加算、攻撃・防御倍率、捨て札参照、手札枚数参照、予約自傷、最大HP減少は共通の効果処理を使用します。捨て札選択はプレイヤーなら手札をクリックし、CPUならAIが選びます。

山札が空になった時点ではなく、空の山札から引こうとした時点で敗北します。手札が上限のときは従来の通常ドローに合わせてドローをスキップします。自傷の「次の自分のターン終了時」は、そのカードを使用したターンの終了時には発動しません。

## 手動で確認する項目

1. CPUが先攻・後攻の場合をそれぞれ試し、初回ドローとコストを確認する。
2. プレイヤーの攻撃にCPUが防御し、CPUの攻撃にプレイヤーが防御・スキップできることを確認する。
3. CPUの使用カードが中央より左に表示され、用途が分かり、短く表示して戻ることを確認する。
4. 双方の攻撃倍率・防御倍率・予約自傷・手札制限を確認し、キャラクタークリックの詳細と実際の消費を比較する。
5. 双方の山札切れ、HP0、手札上限、捨て札選択を確認する。
6. Easy / Normal / Hardの判断とテンポを実際に対戦して調整する。

確認用の自動検証はTools/Validation/CpuBattleChecks.csにあります。実行方法は同じフォルダーのREADME.mdを参照してください。

CPUの攻撃で防御・スキップを選べる場合、カードは拡大位置で選択を待ち、倍率適用後のATK値を表示し続けます。選択を受け付けたらカードを戻し、その後に防御カードの消費とダメージ処理へ進みます。防御の選択肢がない場合と効果・防御・捨て札のカードはHold Duration（初期値1.5秒）だけ表示して戻します。カードの表示は盤面の操作を遮りません。

プレイヤーの手札拡大(CardPopupUI)は専用CanvasのSorting Order 32500を使用し、CPUカード・CPU詳細・操作案内より前に描画します。案内文字が一時的に隠れても、手札カードの本文を読めることを優先します。
