# キャラクターと難易度の選択

対戦開始の順番は、タイトルのスタート → 難易度選択 → キャラクター選択 → 対戦です。既存のStartボタンが呼ぶSceneFlowManager.GoCharacterSelectから難易度パネルを開くため、シーンへの追加配置は不要です。

## 難易度

「やさしい」「ふつう」「むずかしい」を選び、「きゃらくたーをえらぶ」を押すと保存して先に進みます。保存した難易度がCPUの判断と難易度別デッキの選択に反映されます。未選択時の画面初期値は「ふつう」です。

「もどる」またはEscは、変更中の選択を保存せずタイトルに戻します。次回は最後に確定した難易度を表示します。マウスとUnity UIのキーボード操作に対応し、パネルを開いている間は背景のボタンをクリックできません。

Battleシーンを直接実行する場合も、保存済みの難易度を優先します。まだ保存がなければ、BattleStateMachineのInspectorに設定したCpu Difficultyを使用します。

難易度画面は情報空間・電子的な雰囲気に合わせ、青のパネルとボタン、シアンの外枠・上部ライン、薄いデータグリッドを使用します。背景を覆う色の不透明度は0.38とし、タイトルの背景を見やすくしています。選択中は明るいシアンと左側の発光色ラインを表示し、色以外でも選択位置が分かります。画面文言はひらがな表記です。

## キャラクター

選択画面で確定したキャラクターの画像を対戦画面のプレイヤー画像へ反映します。CPUは選択候補のうち別のキャラクターを使用します。効果詳細のタイトルにも、それぞれのCharacterData.displayNameを表示します。

コイントスの先攻条件は、選んだCharacterData.faceForFirstを使用します。配布デッキの対戦では、そのキャラクターのdistributedDeckが固定のシーン設定より優先されます。構築済みデッキがある構築モードでは、プレイヤーが作ったデッキを維持します。CPUデッキは引き続きCPU用設定から選びます。

現在のPicoCharacterDataとNanoCharacterDataは同じBattleDeck_20を参照しています。そのためキャラクターを変えても配布カードの内容は同じです。別のカード構成にしたい場合は、各CharacterDataのDistributed Deckにそれぞれ別のDeckDefinitionを設定してください。今回、カード構成やキャラクターの能力は変更していません。

同じ起動中にキャラクター選択へ戻ると、前に確定したキャラクターを選択状態にします。キャラクター選択はシーンをまたいで保持し、難易度はPlayerPrefsに保存します。

## 検証

Tools/Validation/BattleSelectionChecks.csとSelectionFlowSpy.csで、キャラクター画像・デッキ・先攻条件・難易度保存・画面遷移の呼び出し順・二重遷移防止を検証できます。隔離した検証用プロジェクトへコピーする手順はTools/Validation/README.mdを参照してください。
